# AI агент модуль для ВКР

Данный модуль будет использоваться в ВКР на тему разработка приложения личной активности.

У агента будет свой маскот (возможно будет не один агент и не один маскот тогда).

**Предзащита:** март 2027.

## Стек технологий

| Часть | Технологии |
| --- | --- |
| Frontend | React 19 + TypeScript, Vite, Tailwind CSS v4, Framer Motion |
| Backend | Nest.js (ESM, strict TypeScript), vitest, oxlint |
| Agent | Python 3.12, FastAPI, локальная LLM через Ollama |
| Инфраструктура | Docker, Docker Compose (монорепо) |

## Структура

```
ai-agent-module/
├── frontend/            # React + Vite + Tailwind + Framer Motion  → :5173 (архитектура FSD)
├── backend/             # Nest.js API                              → :3000
├── agent/               # Python AI-агент (FastAPI)                → :8000
├── docker-compose.yml
├── CLAUDE.md            # контекст и правила проекта для Claude Code
└── README.md
```

Поток запросов:

```
frontend  →  backend  →  agent  →  Ollama (на хосте)
```

Фронтенд общается **только** с бэкендом. Бэкенд ходит в агента по адресу `AGENT_URL` (внутри Docker это `http://agent:8000`).

### Почему монорепо
Все три сервиса — части одного модуля и меняются вместе: новая фича агента обычно затрагивает и API, и UI. В монорепо это один коммит, одна команда `docker compose up` и одна ссылка для проверяющего. При этом сервисы изолированы (свои зависимости, свой Dockerfile), так что любой можно вынести в отдельный репозиторий.

## Запуск

Всё сразу через Docker:

```bash
docker compose up --build
```

- Frontend: http://localhost:5173
- Backend: http://localhost:3000
- Agent: http://localhost:8000/health (документация API — http://localhost:8000/docs)

Код подключается в контейнеры через volume, поэтому изменения подхватываются без пересборки (hot reload).

Локально без Docker — см. README в каждой папке.

### Важно при работе с Docker

**Занят порт.** Порты можно переопределить переменными:

```bash
FRONTEND_PORT=5174 docker compose up
```

Также доступны `BACKEND_PORT` и `AGENT_PORT`.

**Установил npm-пакет — пересобери контейнер.** У контейнеров свой `node_modules` (в отдельном volume, не на хосте): пакеты на Mac собраны под macOS, а в контейнере Linux. Поэтому `npm install` на хосте в контейнер не попадает, и Vite/Nest выдаст ошибку вида `Failed to resolve import "..."`. Лечится так:

```bash
docker compose up -d --build --renew-anon-volumes frontend   # или backend
```

Флаг `--renew-anon-volumes` обязателен: без него Docker подставит старый `node_modules`.

## LLM (Ollama)

Агент использует локальную модель через [Ollama](https://ollama.com): API-ключи не нужны, работает офлайн.

- Ollama запускается **прямо на Mac, не в Docker**: на macOS контейнеры не получают доступ к GPU (Metal), и модель работала бы очень медленно.
- Из контейнера агента Ollama доступен по адресу `http://host.docker.internal:11434`.
- Нужна модель с поддержкой tool calling. Машина разработки — Apple M4, 16 GB RAM, так что ориентир на модели ~7–8B.

```bash
ollama serve
```

## Маскоты

Визуальный референс — OpenAI Dots x Higgsfield («Always-On-Agents»):

- плоские векторные фигуры без обводки, теней и градиентов, один яркий цвет на персонажа;
- на лице только глаза, рта нет. Эмоция передаётся формой глаз: `^ ^` радость, `> <` усилие или смущение, `+ +` сосредоточенность, белые овалы — нейтрально;
- «живость» даёт анимация (дыхание, покачивание, моргание), а не детали.

Маскоты рисуются **кодом: inline SVG + Framer Motion**, без картинок и Lottie. Тело и глаза — отдельные слои, поэтому смена эмоции = замена глаз. Цвет и форма задаются параметрами, чтобы новый маскот добавлялся конфигом.

## Агент

Что умеет (план):

1. **Чат-помощник / коуч** — советы, мотивация, ответы про активность пользователя.
2. **Анализ активности** — выводы и отчёты по привычкам, целям, трекингу.
3. **Действия в приложении** — создание задач, целей и напоминаний через tool calling.
4. **Проактивность** — маскот пишет первым («сегодня не отмечена привычка»).

Несколько маскотов — поэтапно:

- **Сейчас:** один агент, пользователь выбирает маскота как «скин» (меняются внешность и тон, логика общая).
- **Потом:** команда агентов со своими специализациями, как в Dots. Поэтому персона маскота (имя, цвет, форма, характер) с самого начала хранится отдельной сущностью.

## Интеграция в основное приложение

Пока не решена, решение ближе к предзащите. Предпочтительный вариант — **встраиваемый виджет**: маскот в углу экрана, чат открывается поверх. Поэтому компоненты маскота и чата делаются самодостаточными (без привязки к роутингу страницы), а всё общение с сервером идёт через один API-клиент с настраиваемым адресом.

## Архитектура frontend: Feature-Sliced Design

Фронтенд организован по методологии [Feature-Sliced Design](https://feature-sliced.design) (FSD). Код делится на **слои** по степени ответственности:

```
frontend/src/
├── app/        инициализация приложения: App.tsx, провайдеры, глобальные стили
├── pages/      страницы целиком
├── widgets/    крупные самостоятельные блоки интерфейса
├── features/   действия пользователя (отправить сообщение, выбрать маскота)
├── entities/   бизнес-сущности (маскот, сообщение)
├── shared/     переиспользуемый код без бизнес-логики: UI-кит, API-клиент, утилиты, токены
└── main.tsx    точка входа Vite
```

### Главное правило
**Слой импортирует только из слоёв ниже себя.** `features` может использовать `entities` и `shared`, но не `widgets` и не другую фичу. Благодаря этому зависимости идут в одну сторону, и любой блок можно поменять, не задев остальные.

### Слайсы и сегменты
Слои `pages`, `widgets`, `features`, `entities` делятся на **слайсы** — папки по смыслу (`entities/mascot`, `features/send-message`). Внутри слайса код разложен по **сегментам**:

| Сегмент | Что лежит |
| --- | --- |
| `ui/` | React-компоненты |
| `model/` | типы, состояние, бизнес-логика |
| `api/` | запросы к серверу |
| `lib/` | вспомогательные функции |
| `config/` | константы |

`app` и `shared` слайсов не имеют и делятся сразу на сегменты.

### Public API
У каждого слайса есть `index.ts` — его публичный интерфейс. Снаружи импортируем только через него:

```ts
import { Mascot } from '@/entities/mascot'          // правильно
import { Mascot } from '@/entities/mascot/ui/Mascot' // нельзя: лезем во внутренности
```

### Почему FSD подходит этому модулю
Модуль, скорее всего, станет **встраиваемым виджетом** в основном приложении ВКР. В FSD виджет чата (`widgets/chat-widget`) собирается из независимых сущностей и фич, поэтому его легко вынести целиком, не таща за собой страницы и глобальное состояние.

### Планируемая раскладка

| Что | Куда |
| --- | --- |
| Компонент маскота, эмоции, персона | `entities/mascot` |
| Сообщение чата | `entities/message` |
| Отправка сообщения | `features/send-message` |
| Выбор маскота | `features/select-mascot` |
| Маскот в углу + панель чата | `widgets/chat-widget` |
| Песочница маскотов | `pages/sandbox` |
| UI-кит (кнопки, поля) | `shared/ui` |
| API-клиент | `shared/api` |
| Дизайн-токены и анимации | `shared/config/theme` |

## Дизайн-система (frontend)

Главный принцип: **интерфейс тихий, цвет живёт только в маскотах.** Нейтральный светлый фон с точечной сеткой, как в референсе, и один акцент.

Все токены — в [`frontend/src/shared/config/theme/tokens.css`](frontend/src/shared/config/theme/tokens.css) (блок `@theme` Tailwind v4). **Стандартная палитра Tailwind отключена:** классы вроде `bg-blue-500` не работают, только токены проекта. Новый цвет — новый токен, а не hex в компоненте.

| Токен | Значение | Где используется |
| --- | --- | --- |
| `canvas` | `#F6F7FA` | фон страницы |
| `surface` | `#FFFFFF` | карточки, сообщения агента, панель чата |
| `line` | `#E6E8EF` | границы, разделители |
| `ink` / `ink-muted` | `#14161F` / `#5E6475` | основной / второстепенный текст |
| `accent` | `#2438C9` | сообщения пользователя, основная кнопка, фокус |
| `accent-soft` | `#E9ECFB` | подложки, выделение |
| `mascot-*` | orange, blue, pink, green, coal, milk | **только** внутри SVG маскотов |

Кобальт `#2438C9` выбран вместо синего Instagram (`#3797F0`): белый текст на нём даёт контраст 8.45:1, а у Instagram всего 3.07:1 (норма WCAG — 4.5:1).

- **Шрифты:** Onest (`font-sans`) — весь интерфейс; Unbounded (`font-display`) — только имена маскотов и крупные заголовки. Подключены локально через `@fontsource-variable`, без CDN, чтобы работать и внутри виджета.
- **Скругления:** `rounded-control` 14px (кнопки, поля), `rounded-bubble` 20px (сообщения), `rounded-card` 24px (карточки).
- **Фон:** утилита `bg-dots` — точечная сетка.
- **Анимации:** параметры в `frontend/src/shared/config/theme/motion.ts` — `springBouncy` для маскотов, `springCalm` для интерфейса.
- **Тема:** пока только светлая. Токены названы по смыслу, поэтому тёмную можно добавить переопределением тех же переменных.

### Импорты

В `frontend` настроен алиас `@/` → `src/`:

```ts
import { motionTokens } from '@/shared/config/theme'
```

Алиас задан в двух местах — `paths` в `tsconfig.app.json` и `resolve.alias` в `vite.config.ts`. Менять их нужно вместе.

## Соглашения

- **backend** — ESM: относительные импорты пишутся с расширением `.js` (`import { AppModule } from './app.module.js'`).
- **agent** — версии зависимостей фиксируются в `requirements.txt`, локально используется `.venv`.
- Новые переменные окружения прописываются в `docker-compose.yml` и описываются в README сервиса.
