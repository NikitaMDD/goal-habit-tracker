# CLAUDE.md

AI-агент с маскотом — модуль для ВКР «Разработка приложения личной активности».
Предзащита — март 2027. Общение с пользователем и UI — на русском.

## Структура (монорепо)

```
frontend/   React 19 + TypeScript + Vite, Tailwind v4, Framer Motion   :5173
backend/    Nest.js (ESM, strict TS)                                    :3000
agent/      Python 3.12 + FastAPI, LLM через Ollama                     :8000
docker-compose.yml
```

Поток запросов: `frontend → backend → agent → Ollama`. Фронтенд ходит **только** в backend; агент наружу не торчит, бэкенд обращается к нему по `AGENT_URL`.

## Команды

```bash
docker compose up --build                 # всё сразу
FRONTEND_PORT=5174 docker compose up      # если 5173 занят (на этой машине его держит другой проект)

# после установки npm-пакета — обновить node_modules в контейнере (он лежит в анонимном volume, не на хосте):
docker compose up -d --build --renew-anon-volumes frontend   # или backend

cd frontend && npm run dev | build | lint
cd backend  && npm run start:dev | build | lint | test | test:e2e
cd agent    && .venv/bin/uvicorn app.main:app --reload
```

## Продукт

### Маскоты
Визуальный референс — OpenAI Dots x Higgsfield («Always-On-Agents»):
- плоские векторные фигуры **без обводки, теней и градиентов**, один яркий цвет на персонажа (оранжевый «цветок», синий треугольник, чёрный круг, розовый многоугольник, зелёная капля с ростком, маленький белый мишка);
- лицо — **только глаза, без рта**. Эмоция передаётся формой глаз: `^ ^` радость, `> <` усилие/смущение, `+ +` сосредоточенность, белые овалы — нейтрально;
- мягкие скруглённые формы, персонаж «живой» за счёт анимации, а не деталей.

Реализация: маскоты рисуются **кодом — inline SVG + Framer Motion** (не PNG, не Lottie). Тело и глаза — отдельные слои: эмоция = смена компонента глаз, idle = дыхание/покачивание/моргание. Цвет и форма — параметры, чтобы новый маскот добавлялся конфигом.

### Агент
Возможности (все четыре в скоупе):
1. Чат-помощник / коуч — советы, мотивация, ответы про активность пользователя.
2. Анализ активности — выводы и отчёты по привычкам, целям, трекингу.
3. Действия в приложении — создание задач/целей/напоминаний через tool calling.
4. Проактивность — маскот пишет первым («сегодня не отмечена привычка»).

Мультимаскотность — поэтапно:
- **Сейчас:** один агент, пользователь выбирает маскота-«скин» (меняется внешность и тон, логика общая).
- **Потом:** команда агентов со специализациями, как в Dots. Поэтому уже сейчас персона маскота (имя, цвет, форма, характер/системный промпт) — отдельная сущность, а не хардкод.

### LLM
Локальная модель через **Ollama** (ключи не нужны, работает офлайн). Нужна модель с поддержкой tool calling.
Ollama запускается **нативно на хосте**, не в Docker: на macOS контейнеры не получают доступ к GPU (Metal). Из контейнера агента — `http://host.docker.internal:11434`.
Машина разработки: Apple M4, 16 GB RAM → ориентир на модели ~7–8B.

### Интеграция в основное приложение ВКР
Не решено (решится ближе к марту 2027). Предпочтение — **встраиваемый виджет** (маскот в углу экрана, чат открывается поверх). Поэтому:
- компоненты маскота и чата делать самодостаточными, без привязки к роутингу/глобальному состоянию страницы;
- всё общение с сервером — через один API-клиент с настраиваемым base URL.

## Соглашения
- **backend** — ESM (`"type": "module"`): относительные импорты с расширением `.js` (`import { AppModule } from './app.module.js'`). Линтер — oxlint, тесты — vitest.
- **frontend** — Tailwind v4 через `@tailwindcss/vite`, конфиг-файла нет. Анимации — `framer-motion`.
  - **Архитектура — Feature-Sliced Design (FSD).** См. раздел «Frontend: FSD» ниже.
  - **Дизайн-токены** — `src/shared/config/theme/tokens.css` (`@theme`) — единственный источник цветов/шрифтов/радиусов/теней. Стандартная палитра Tailwind сброшена (`--color-*: initial`), поэтому `bg-blue-500` не существует — только `bg-canvas`, `text-ink`, `bg-accent`, `rounded-bubble` и т.д. Новый цвет = новый токен, не hex в компоненте.
  - Интерфейс тихий: нейтральные + один акцент (кобальт `accent`, сообщения пользователя и основная кнопка). Яркие `mascot-*` цвета — только внутри SVG маскотов.
  - Параметры анимаций — `src/shared/config/theme/motion.ts` (`springBouncy` для маскотов, `springCalm` для UI), импорт — `import { motionTokens } from '@/shared/config/theme'`.
  - Импорты из `src` — через алиас `@/`, без `../../` (исключение — `@import` в CSS, там относительные пути). Алиас задан в двух местах: `paths` в `tsconfig.app.json` и `resolve.alias` в `vite.config.ts` — менять синхронно.
  - Шрифты: Onest (`font-sans`, весь UI), Unbounded (`font-display`, только имена маскотов и крупные заголовки). Подключены через `@fontsource-variable`, без CDN.
  - Пока только светлая тема; токены семантические, тёмную можно добавить переопределением тех же переменных.
- **agent** — зависимости пинятся в `requirements.txt`, локально `.venv`.
- Новые переменные окружения — прописывать в `docker-compose.yml` и упоминать в README сервиса.

## Frontend: FSD

Слои (сверху вниз). **Слой может импортировать только из слоёв ниже себя**, никогда — из своего уровня или выше:

```
src/
├── app/        инициализация: App.tsx, провайдеры, глобальные стили (app/styles/index.css)
├── pages/      страницы целиком (sandbox, …)
├── widgets/    крупные самостоятельные блоки UI (chat-widget)
├── features/   действия пользователя, приносящие ценность (send-message, select-mascot)
├── entities/   бизнес-сущности (mascot, message, persona)
├── shared/     переиспользуемое без бизнес-логики: ui, api, lib, config (theme)
└── main.tsx    точка входа Vite — только рендер <App />
```

`app` и `shared` делятся сразу на **сегменты**. Остальные слои — на **слайсы** (по сущности/фиче, kebab-case), а слайсы — на сегменты:
- `ui/` — компоненты; `model/` — типы, состояние, логика; `api/` — запросы; `lib/` — хелперы; `config/` — константы.

Правила:
- **Public API:** у каждого слайса есть `index.ts`, наружу импортируется только через него: `import { Mascot } from '@/entities/mascot'`, не `'@/entities/mascot/ui/Mascot'`. Внутри своего слайса — относительные импорты.
- **Слайсы одного слоя не импортируют друг друга** (feature не знает о другой feature). Нужна связь — поднимать в слой выше (widget/page) или опускать общее в `entities`/`shared`.
- `shared` не знает о бизнесе: никаких маскотов и сообщений в `shared/ui`.
- **Роутинг (React Router v8) — только в `app/router` и `pages`.** `widgets`/`features`/`entities` не используют `useNavigate`, `Link` и т.п.: виджет будет встраиваться в чужое приложение со своим роутером.
- Склейка классов — `cn()` из `@/shared/lib` (clsx + tailwind-merge, настроенный на наши токены `rounded-*`/`shadow-*`). Варианты компонентов — объект-словарь классов, без доп. библиотек.
- Не создавать слой/сегмент «на будущее» с одним файлом без нужды — FSD допускает пропуск слоёв.

Планируемая раскладка:
| Что | Куда |
| --- | --- |
| `<Mascot>` (SVG тело + глаза), типы эмоций, персона маскота | `entities/mascot` |
| Сообщение чата (пузырь, тип) | `entities/message` |
| Отправка сообщения | `features/send-message` |
| Выбор маскота-«скина» | `features/select-mascot` |
| Виджет: маскот в углу + панель чата | `widgets/chat-widget` |
| Песочница маскотов/эмоций | `pages/sandbox` |
| Кнопки, инпуты и прочий UI-кит | `shared/ui` |
| Иконки — inline SVG, без библиотек, цвет `currentColor`, размер классом `size-*` | `shared/ui/icon` |
| Форматирование времени/длительности, `clamp` | `shared/lib` |
| API-клиент с настраиваемым base URL | `shared/api` |
| Заглушка бэкенда (задержки + 20% сбоев), пока нет API — заменить на `shared/api` | `widgets/chat-widget/api/fakeAgent.ts` |
| Токены (`tokens.css`, `motion.ts`) | `shared/config/theme` |

## Инструкция для работы с кодом

- Не пуш коммиты
- Не создавать коммиты, только придумывать их названия если попросят
- Не исправлять код самостоятельно только показывать его, тоже самое касается и чистого написания кода (это правило не касается файлов с расширение .css)
